# UI design spec

**Owner: the capture UI.** This is the visual system the UI is built against, extracted from the working prototype (Hallmark design system, theme "Midnight").
It covers appearance only. Behavior, read/write privileges, and the day boundary are `ui-contract.md`; this file never overrides it.

Design name: **Midnight**.
Genre: atmospheric, dark-first, instrument-grade.
Tone: technical, not decorative. The chrome should read like a cockpit, not a stationery set.

## Color

All colors are defined in OKLCH, not hex or RGB. Two full palettes exist: dark is the base, light is "the courtesy drop", generated by re-deriving the same roles rather than inverting values.

Canvas neutrals carry a cool-violet hue (H 265). The single accent is warm brass (H 68 dark-mode, H 58 in light-mode). Nothing else carries hue. That is the entire palette: nine neutral steps plus one accent, in each theme.

### Dark (default)

| Token | Value | Role |
|---|---|---|
| `--color-paper` | `oklch(14% 0.012 265)` | app background |
| `--color-paper-2` | `oklch(17.5% 0.014 265)` | raised surface (panels, chips, blocks) |
| `--color-paper-3` | `oklch(21% 0.015 265)` | pressed / active surface |
| `--color-rule` | `oklch(26% 0.013 265)` | hairline dividers |
| `--color-rule-2` | `oklch(34% 0.014 265)` | stronger borders (buttons, inputs) |
| `--color-muted` | `oklch(68% 0.012 265)` | secondary text, labels |
| `--color-ink-2` | `oklch(84% 0.008 265)` | body text |
| `--color-ink` | `oklch(96% 0.006 265)` | headings, primary text |
| `--color-accent` | `oklch(78% 0.145 68)` | the one signal color: current nav, open state, recurrence, warnings |
| `--color-accent-wash` | `oklch(24% 0.045 68)` | accent tinted onto a paper surface (banners, verdict blocks) |
| `--color-focus` | `oklch(80% 0.145 68)` | focus ring, same as accent |

### Light (courtesy drop)

Same roles, re-derived, not inverted: `--color-paper` becomes `oklch(97% 0.006 265)`, `--color-ink` becomes `oklch(19% 0.016 265)`, accent shifts to `oklch(45% 0.145 58)` because a saturated brass that reads as a glow on black reads as mud on white at the same lightness. Every token has an explicit light-mode value; none are computed by inversion or opacity tricks.

### The rule on accent

Accent is a signal, not a decoration. It appears in exactly these places: the current nav item's left border and background wash, an "open" (unsealed) status stamp, a recurring-field border, the command-palette focus ring, and verdict/proposal blocks. It never appears on body text, never as a second button color, never as a heading color. A page with two accent-colored things competing for attention is a bug.

### The one atmospheric element

`--canvas-bloom`: a single fixed radial gradient, accent-tinted at 5.5% opacity dark / 5% light, positioned at 22% 4% (upper-left), fading to nothing by 45% of its radius. This is the *only* enrichment element in the whole shell. It sits behind the main column, `background-attachment: local`, and never moves, animates, or repeats. One bloom, not a texture.

## Typography

Two families only: a grotesk sans for everything humans read as prose or UI, and a mono for everything that is data, a label, or a timestamp.

```
--font-sans: "Geist", ui-sans-serif, -apple-system, system-ui, sans-serif;
--font-mono: "JetBrains Mono", ui-monospace, "SF Mono", Menlo, monospace;
```

### Scale

| Token | Size | Used for |
|---|---|---|
| `--text-xs` | 0.6875rem (11px) | mono labels, meta, timestamps, chips |
| `--text-sm` | 0.8125rem (13px) | secondary body, nav items, buttons |
| `--text-base` | 0.9375rem (15px) | UI body default, block titles |
| `--text-prose` | 1.125rem (18px) | the entry-writing surface itself |
| `--text-md` | 1.375rem (22px) | section headings (weekly/monthly/quarterly) |
| `--text-lg` | 1.75rem (28px) | page title, verdict statement |

Ratio between adjacent steps is not a fixed multiplier; it is chosen per hop (roughly 1.18, 1.15, 1.2, 1.22, 1.27 walking up the scale), tightening at the small end where legibility is the constraint and opening up at the top where only one or two headings exist per screen.

### Line height and tracking

- `--lh-tight: 1.1` — headings only.
- `--lh-snug: 1.4` — UI text, the document default.
- `--lh-body: 1.7` — prose registers only (the entry textarea, review narrative, quotes). Long-form reading gets almost double the leading of UI chrome.
- `--track-tight: -0.03em` on all headings. Body copy carries no tracking; mono labels carry `+0.16em` to `+0.02em` positive tracking (uppercase micro-labels get the widest: 0.16em).

### The micro-label pattern

Every section eyebrow (`SEALED`, `COUNTED BY THE REVIEW`, `PROPOSAL`) is mono, `--text-xs`, weight 500, `letter-spacing: 0.16em`, uppercase, colored `--color-muted` (or `--color-accent` when it is flagging something). This one recipe is reused everywhere rather than inventing a new label style per section.

## Space

An 11-step scale, each step a fixed rem value, not a multiplier chain:

```
--space-3xs: 0.125rem   (2px)
--space-2xs: 0.25rem    (4px)
--space-xs:  0.5rem     (8px)
--space-sm:  0.75rem    (12px)
--space-md:  1rem       (16px)
--space-lg:  1.5rem     (24px)
--space-xl:  2.5rem     (40px)
--space-2xl: 4rem       (64px)
--space-3xl: 6rem       (96px)
```

Two deliberate jumps break a clean geometric progression: `md -> lg` is 1.5x (16 to 24) and `lg -> xl` is 1.67x (24 to 40), wider than the 1.33-1.5x steps below them. That gap is where "tight UI chrome" ends and "negative space around content" begins. Everything at `md` and below is control spacing: gaps inside a button row, padding inside a chip. Everything at `xl` and above is page-level air: the top padding of the main column (`--space-3xl`, 96px), the gap between major blocks (`--space-xl`, 40px).

### The negative-space rule

The reading column (`.col`) is capped at `74ch` (about 640px at this type scale) and centered, with 96px of top padding and 40px of horizontal padding on desktop. A wide variant (`.col--wide`, 96ch) exists only for tabular review content. Prose never runs full-bleed. The width cap is the primary negative-space device in this system, not margin tricks: constrain the measure, then let vertical rhythm (the `xl`/`2xl`/`3xl` steps) do the rest.

Section content inside a page uses one `flex-direction: column; gap: var(--space-xl)` — a single flat gap value between all top-level blocks on a page, never per-pair custom margins. Internal block content (a `.block`, a `.note`) uses `--space-sm` between its own child rows. That is the two-tier rule: `sm` inside a component, `xl` between components, nothing in between except where a specific composite (nav rail sections at `xl`, cadence grid gaps at `3xs`) demands it.

## Sizing and ratios

Five fixed control heights, not derived from type size:

```
--size-dot:  6px    dot indicator inside a stamp
--size-chip: 24px   frontmatter field / status chip height
--size-ctl:  32px   icon button, search pill, primary button height
--size-tap:  44px   minimum hit target (via ::before inset expansion on icon buttons)
```

Ratios worth naming:
- `chip : ctl = 3 : 4` (24:32). A chip is three-quarters the height of a control button, deliberately smaller because it displays data rather than inviting a click.
- `ctl : tap = 8 : 11` (32:44). Every icon button renders at 32px visually but its hit target is padded out to the 44px accessibility minimum via an invisible `::before` inset of `(44-32)/-2 = -6px` on all sides. The visible control never grows to meet the tap target; the tap target grows invisibly around it.
- Buttons are not square: height is fixed at `--size-ctl` (32px) but horizontal padding is `--space-sm` (12px) each side, so a button's width is content-width plus 24px, never a fixed square. Icon-only buttons are the exception and are exactly square: 32x32.

Radii, three steps, used by role, not by component size:
```
--radius-sm:   4px    controls: buttons, chips, icon buttons, kbd
--radius-md:   8px    surfaces: blocks, panels, notes, the command palette
--radius-pill: 999px  the search pill only
```
No radius step is skipped or interpolated. A component is either a control (4px), a surface (8px), or the one pill-shaped element in the whole system.

Borders are a single hairline weight, `--rule-hair: 1px`, always solid, never doubled or varied by emphasis; emphasis is carried by color (`--color-rule` vs `--color-rule-2`), not by width.

## Layout grid

The shell is a single CSS grid, three columns by three rows:

```
rail (248px)  |  main (flexible) |  aside (316px)
------------------ top bar spans all three ------------------
------------------ status bar spans all three -----------------
```

Rail and aside are fixed-width, not proportional: `--rail-open: 248px`, `--aside-open: 316px` (narrowing to 288px under 78rem / 1248px viewport width). Only `main` is `minmax(0, 1fr)`. Collapsing either panel sets its width variable to `0px` rather than toggling `display`, so the grid transition is a width animation, not a reflow snap.

### Breakpoints

- `78rem` (1248px): aside narrows 316px -> 288px, rail unchanged.
- `64rem` (1024px): grid collapses to a single column, stacking `top / main / rail / aside / status`. Rail and aside become full-width collapsible sections below the content, not beside it. This is the point where reading the entry takes priority over navigating between entries.
- `30rem` (480px): search pill loses its label and shrinks to icon-only; column padding drops from `--space-xl` (40px) to `--space-md` (16px); page title drops one type step (`--text-lg` to `--text-md`).

Verified render widths: 320, 375, 414, 768, plus the two breakpoints above.

## Motion

Three primitives only, no fourth invented per-view:
1. **Fade-reveal on load**: `opacity: 0 -> 1` over `--dur-long` (420ms), `--ease-out`, staggered by `calc(var(--i, 0) * 60ms)` per element. Used once per view, on first paint.
2. **Panel content fade**: rail/aside inner content fades to `opacity: 0` when its panel collapses, `--dur-short` (220ms).
3. **Row/control hover and press**: background-color and color transitions at `--dur-micro` (120ms) on hover, plus a `translateY(1px)` press state on buttons. No hover scale, no shadow-on-hover.

There is deliberately no spatial slide, no view transition, no parallax. That is a genre rule for this shell, not an oversight: an atmospheric/instrument-grade UI earns its stillness. `prefers-reduced-motion: reduce` clamps every duration to 150ms and disables iteration, globally, in one rule.

Easing curves:
```
--ease-out:    cubic-bezier(0.16, 1, 0.3, 1)   entrances
--ease-in:     cubic-bezier(0.7, 0, 0.84, 0)   exits
--ease-in-out: cubic-bezier(0.65, 0, 0.35, 1)  state toggles
```

## Elevation

No drop shadows on ordinary surfaces. Elevation is expressed by background-color step alone: `paper -> paper-2 -> paper-3` is the entire elevation system for panels, blocks, and pressed states. The single shadow token, `--lift` (`0 24px 60px -30px black at 70% opacity`, dark mode), exists only for the command palette, the one element that floats above the whole shell on a scrim.

## Semantic distinctions that must survive redesign

- **The review tiers differ in shape, not just content.** Weekly renders as findings (`.block` list), monthly as trend (`.trend` bars), quarterly as verdict (one `.verdict` block plus `.check` list). A redesign that makes all three tiers look like the same list template has broken the point of having three tiers.
- **A missing day is a void, not an empty state.** `.voidrow` and `.datechip--void` render as a bare label plus a hairline rule, visually quieter than any real entry, never as a placeholder card or a skeleton loader. The absence itself is the content.
- **Sealed vs. open is a status stamp, never a locked-icon metaphor.** The `.stamp--open` state is the only place accent-wash appears on a small chip; sealed entries get the neutral stamp. No padlock iconography anywhere in the system.
- **Never color alone.** Done-condition checks (`.check__m--met` / `--miss`) and any other binary state pair a text/mono marker with color, so the distinction survives grayscale and colorblind rendering.

## Copy typography

No em dashes anywhere in UI copy or generated content. Clauses join with commas, colons, or full stops. This is a hard rule, checked on every pass, not a style preference to be revisited per feature.

## What this file is not

This is not a component library and not implementation code. It is the ratio and token system a UI must reproduce to be recognizably "this app." A UI that hits every acceptance test in `ui-contract.md` but ignores this file will function correctly and look like a different, worse product. Treat divergence from these tokens as a design regression with the same seriousness as a failed acceptance test.
